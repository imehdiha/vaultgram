# Security model

Vaultgram uses Cloudflare Worker Secrets for the Telegram token, webhook secret, Owner bootstrap secret, PIN pepper, and 256-bit `VAULT_ENCRYPTION_KEY`. Never commit, log, or put these values in D1, KV, or `wrangler.jsonc`. The key generator prints new random values only once; it cannot recover a previously configured key. **If `VAULT_ENCRYPTION_KEY` is lost, stored documents and Secure Values cannot be decrypted.** Back it up in a trusted password manager or offline secret store, separate from the repository. A D1/KV backup without the key is insufficient, as is a key without the matching data.

The fresh-install wizard writes a single recovery JSON file under the user's home directory with mode `0600`, outside the repository. It contains all five Secret values, including the bot token. Save it in a password manager and delete the local copy after installation and backup verification if appropriate. The ignored `.vaultgram/` directory contains a Wrangler config and resume state, but no Secret values. The wizard refuses a bot with an existing webhook, checks that its generated Worker name is unused, and resumes partial installs with their original values rather than generating replacement keys.

Document bytes are encrypted in 256 KiB AES-256-GCM chunks before being streamed into KV. A random nonce prefix and chunk counter provide unique IVs within a version. Every version uses a new random storage key and a derived per-version key. Additional authenticated data binds each chunk to its vault, document, storage key, size, and index; altered or swapped ciphertext fails authentication. Secure Values use a separate HKDF domain, random IV, and revision-specific key with authenticated vault/value identity. Their labels and metadata remain plaintext in D1; their values do not.

The Owner sees all Vaults. Members see only Vaults explicitly granted. The Worker rechecks D1 ACLs before document and Secure Value operations. PIN unlock is an optional second check. PINs are salted HMAC values with a Worker-only pepper, five-attempt lockout, and expiring unlock sessions. The webhook verifies Telegram's secret header and accepts only private chats. Invite tokens are hashed, one-time, and expiring. Destructive actions use expiring confirmation records.

`protect_content` is enabled by default for delivered documents and Secure Values. A Queue job stores only the chat and message IDs needed for delayed deletion. Telegram input containing a Secure Value is deleted after encrypted persistence when Telegram permits; a failure is reported to the user. Telegram and Cloudflare still process plaintext during upload/retrieval, and Telegram may retain messages under its policies. `protect_content` does not prevent screenshots or compromised devices. This is not end-to-end encryption against Telegram, Cloudflare runtime operators, or the trusted Vaultgram Owner.

The bot also attempts to delete incoming text messages and superseded navigation menus. Temporary bot prompts are removed after an answer when possible and are scheduled for deletion after 120 seconds. Telegram can reject deletions; this does not erase data already processed by Telegram.

KV is eventually consistent. Immutable keys prevent stale overwrites, but a new object can be temporarily unavailable in another location. The bot asks the user to retry during a propagation window; later missing objects can be reconciled. The Worker uses a 20,000,000-byte incoming limit, below Telegram's 20 MB hosted download limit and KV's 25 MiB value limit. Check current [KV limits](https://developers.cloudflare.com/kv/platform/limits/) and [KV consistency](https://developers.cloudflare.com/kv/concepts/how-kv-works/) before increasing limits.

On Telegram token exposure, rotate it in BotFather, update the Worker Secret, and register the webhook again. On webhook or bootstrap secret exposure, rotate the affected Worker Secret and webhook as applicable. On `VAULT_ENCRYPTION_KEY` exposure, plan an authenticated re-encryption migration; changing the secret alone makes existing data unreadable. Changing `PIN_PEPPER` requires PIN resets. Avoid logging file contents, Secure Values, Telegram tokens, or Worker secrets while diagnosing failures.
